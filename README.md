# ⚔️ MetalMC

> **A performance-focused fork of [Paper](https://github.com/PaperMC/Paper)**

## 📖 Overview

MetalMC is built on the latest Paper for **Minecraft 26.3**. It keeps full compatibility with Bukkit, Spigot and Paper plugins.

MetalMC is a proper paperweight fork. Instead of a copy of Paper's source tree, it pins one upstream Paper commit (`paperCommit` in `gradle.properties`) and keeps its own changes as small patch files on top. Updating to a newer Paper or Minecraft version is mostly a matter of changing that commit hash.

---

## ✨ What you get

### Everything in Paper

Every Paper performance patch is included, for example:

-   **Moonrise chunk system:** multithreaded chunk loading, generation and I/O.
-   **Alternate Current redstone:** a much faster redstone wire implementation.
-   **Optimized hoppers, voxel shapes, collisions, POI lookups, pathfinding and entity scheduling.**
-   **Entity Activation Range 2.0** and per-player mob spawning.
-   **Velocity compression and cipher natives** for networking.
-   **Anti-Xray.**

### Faster defaults

A fresh MetalMC install ships with performance-oriented defaults in `config/paper-world-defaults.yml`. Existing configs are never overwritten. Only keys you haven't set use these defaults.

| Setting                                    | Paper     | MetalMC             | Why                                                                                     |
| ------------------------------------------ | --------- | ------------------- | --------------------------------------------------------------------------------------- |
| `misc.redstone-implementation`             | `VANILLA` | `ALTERNATE_CURRENT` | Much less CPU for redstone dust, with vanilla-like behavior.                            |
| `environment.optimize-explosions`          | `false`   | `true`              | Caches explosion density lookups, which helps a lot with TNT.                          |
| `chunks.prevent-moving-into-unloaded-chunks` | `false` | `true`              | Stops players from forcing synchronous chunk loads by moving into unloaded chunks.    |
| `chunks.entity-per-chunk-save-limit`       | unlimited | xp orbs 16, arrows 16, snowballs 8, fireballs 8 | Stops projectile spam in one chunk from stalling saves and loads. Ender pearls stay unlimited so stasis chambers keep working. |

To get Paper's behavior back, set the value in `config/paper-world-defaults.yml` (or a per-world `paper-world.yml`). For example, `redstone-implementation: VANILLA` restores exact vanilla redstone update order for technical contraptions that depend on it.

### Tuned launcher

`scripts/start.sh` (Linux/macOS) and `scripts/start.bat` (Windows) start the server with [Aikar's G1 flags](https://docs.papermc.io/paper/aikars-flags). They also turn on **compact object headers** (`-XX:+UseCompactObjectHeaders`, new in Java 25), which make every Java object 4 bytes smaller and reduce memory use and GC work.

## 📥 Installation

1.  **Java:** install **Java 25** or newer.
2.  **Download:** get `metalmc-26.3.jar` (plus `start.sh` / `start.bat`) from the [latest release](../../releases/latest), or build it yourself (below).
3.  **Run:**
    ```bash
    MEMORY=6G ./start.sh metalmc-26.3.jar
    ```
    `MEMORY` sets the heap size (default `4G`). On Windows, run `set MEMORY=6G` and then `start.bat`.

## 📦 Building from source

You need Git and Java 25.

```bash
git clone https://github.com/Just-Haze/MetalMC.git
cd MetalMC
./gradlew applyAllPatches      # checks out Paper at paperCommit and applies MetalMC's patches
./gradlew createPaperclipJar   # builds metalmc-server/build/libs/metalmc-<version>.jar
```

### Project layout

| Path                                   | Contents                                                                    |
| -------------------------------------- | --------------------------------------------------------------------------- |
| `gradle.properties`                    | `mcVersion` and the pinned upstream `paperCommit`.                          |
| `metalmc-server/build.gradle.kts.patch` | Changes to Paper's server build (branding, jar name).                       |
| `metalmc-server/paper-patches/`        | Patches to Paper's own server code (CraftBukkit, Paper config, ...).        |
| `metalmc-server/minecraft-patches/`    | Patches to Minecraft's code (created on demand; see below).                 |
| `metalmc-api/paper-patches/`           | Patches to the Paper API.                                                   |
| `paper-api/`, `paper-server/`, `metalmc-server/src/minecraft/` | Generated by `applyAllPatches` (git-ignored). Edit these, then rebuild patches. |

### Making changes

1.  Run `./gradlew applyAllPatches`.
2.  Edit the generated sources:
    -   Minecraft code: `metalmc-server/src/minecraft/java`. This is a git repo; commit your change there.
    -   Paper server code: `paper-server/`.
    -   Paper API code: `paper-api/`.
3.  Turn your edits into patches with `./gradlew rebuildAllServerPatches` (server) or `./gradlew rebuildPaperPatches` (API and Paper files).
4.  Commit the patch files in `metalmc-*/`.

### Updating to a newer Paper / Minecraft version

1.  Set `paperCommit` in `gradle.properties` to the new Paper commit, and `mcVersion` / `apiVersion` if the Minecraft version changed.
2.  Run `./gradlew applyAllPatches`. If a MetalMC patch no longer applies, fix it in the generated sources and rebuild the patches as above.

### Publishing a release

1.  Write the release notes in `.github/release-notes/<tag>.md`, for example `v26.3-1.md`.
2.  Push the tag: `git tag v26.3-1 && git push origin v26.3-1`.

The [Release workflow](.github/workflows/release.yml) builds the jar, boots it once as a smoke test, and publishes a GitHub release. The release includes `metalmc-<mc version>.jar`, the start scripts and SHA-256 checksums.
